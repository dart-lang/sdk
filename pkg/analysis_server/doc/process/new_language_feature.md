# Implementing a new language feature in the analysis server

When a new language feature is approved, a top-level tracking issue will be
created to track the work required for the Developer Experience team. That issue
will have sub-issues for the tools maintained by the team.

The templates for the issues are in the
[Language Features template](https://github.com/orgs/dart-lang/projects/113/views/1)
project.

## Existing functionality

Those sub-issues will often have check-lists for all of the existing pieces that
need to be considered, with instructions to evaluate each piece to see whether
it is impacted by the new feature. The purpose of the check boxes is to track
whether the piece of functionality has been evaluated. If no work needs to be
done for the feature, then the check box can be checked and there's no further
work to do. If there is work that needs to be done, then create a child issue to
track the work and check the box.

## New functionality

A few of the issues are there to track new features, such as new fixes or
assists. When there is an idea for a new feature, a child issue should be
created for it and discussion about whether it is worth adding should happen in
the child issue.
